# Evidence-led prose

Create a factual draft from the approved ledger, with audience, user problem, verified behavior and limits. This is an internal composition step and loads no vendor Skill by default. Do not manufacture weak prose to demonstrate an editor.

Only when prose needs the distinctive humanizer review, load `vendor/humanizer/SKILL.md` and use its embedded/file mode. The editor does not discover facts. The following workflow applies only to that explicitly routed optional review.

1. Mark structural and sentence-level tells over the whole draft, strongest first. Preserve the marked draft.
2. Rewrite supported claims for the real reader. Preserve facts, citations, uncertainty, commands and link targets; add no claims.
3. Read the draft naturally and recheck surviving contrasts, closers, triads, dashes and labels. Compare every claim with the input ledger; fix additions/losses.
4. Write final natural prose. Preserve before/draft/fact-check/final evidence and its README/docs consumer.

Use neutral technical voice without a writing sample. A clean input may need few edits; record review instead of adding artificial mistakes or forcing change.
