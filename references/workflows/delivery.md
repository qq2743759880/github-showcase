# Local evidence and delivery

For Agent Skill projects, first apply `references/distribution-surfaces.md`: declare Runtime/Showcase/private evidence, produce the generic Minimal Runtime artifact from current source, fresh-extract and verify it, and use the Agent Skill README Profile. Full release gate checks those surfaces and the current runtime receipt in addition to existing gates. After publication, verify the downloaded runtime release asset and actual documented first use; do not substitute code/mixed install/test stages for a method package.

1. Scan only the approved export. Run `scripts/verify-vendors.py`; review licenses, privacy, excluded paths and public claims. The secret engine is a utility, not all safety axes. Blocking findings stop delivery; do not open real secret values or bypass rejection with a reviewer. The only fixture exception is the exact content-bound security-test contract below; native scanner rules and raw findings remain intact.
2. Save the final README and assets before receipts. A comprehension reviewer sees only that README and answers what/problem/input/output/difference with exact quotes. Store JSON with `kind: reader-comprehension`, `status: PASS`, `independent: true`, reviewer, `readme_sha256` and five answers. Use `scripts/evidence.py` for hashes.
3. Record each integrated workflow in `fidelity-trace.json`: `routed_core`, one call per Skill, `loaded_resources`, all obligations with observations and hashed relative evidence, outputs with hashes and final consumer/link. Run `python scripts/skill-fidelity.py <trace> <export> --output <receipt>`. Independently review meaning and distinctive output; a structural trace is not a semantic score.
4. For code/mixed exports include entry points and dependency manifests. Commit the approved local export, clone to a new directory, install runtime and verification dependencies separately, prepare a safe example configuration, start and test. Store a `fresh-clone` JSON receipt bound to `export_digest` and commit, with a relative `clone_dir` beneath the receipt directory and six successful steps (`clone`, `runtime-install`, `setup`, `start`, `verification-install`, `tests`), commands and hashed logs. The gate checks the actual independent clone HEAD and tracked source bytes against the final export. No historical test count.
5. Run `release-gate.py <export> --policy <policy> --showcase-gate --comprehension-receipt <json> --fidelity-receipt <json> --fresh-clone-receipt <json>`. Declare project_kind, routed_assets, source_release when code, private_literals and license status. Fidelity is mandatory for a full Showcase gate; its receipt contains relative `trace_path`, and the gate rechecks the trace and all hashed evidence. Self-release adds `--require-self-dogfood --self-dogfood-receipt <json>` bound to run, relative fidelity receipt, `fidelity_sha256`, current product_digest (excluding local usage) and final export_digest. Changed evidence fails.
6. Package the clean local export with `package-project.py` and the same evidence paths. Keep receipts outside public export. After explicit publication authorization follow `publish-backends.md` and verify remote content/commit/CI. A local PASS is never PUBLISHED_VERIFIED.

Machine validators check content consistency and recorded execution. They cannot infer reviewer independence or execution from prose alone; require a real separate review and command traces in the report.

## Verified synthetic security findings

Release policy optionally declares `secret_fixture_exemptions`. Each approved item has exactly `path`, `rule_id`, `fixture_sha256`, `line_sha256`, `line`, `column`, `classification`, `purpose`. Paths are exact canonical export-relative test source (`tests/`, `test/`, or `fixtures/security/`, .py/.js/.mjs/.ts); classification is `security-test-fixture`; purpose explains the actual negative test. `fixture_sha256` is SHA256 of the exact upstream matched UTF-8 value, including any literal delimiter captured by its regex. `line_sha256` is SHA256 of the complete decoded line without newline. Line/column bind one finding, not a file or directory. Preserve engine redaction; do not publish raw credentials or approval evidence.

Only `basic-auth-url` findings with independently inspected synthetic inputs are supported. The bounded synthetic grammar uses HTTPS, literal placeholder users `user` / `test_key_user`, placeholder passwords `secret` / `pass` / `test_key_password`, and exact example hosts `example.com`, `example.invalid`, `fixture.trycloudflare.com`, `example.ngrok.dev`. This grammar alone grants no bypass: the current rule/path/position/two SHA/purpose/classification must also match a reviewed approval. Other rules, critical secrets, production paths, long-line location transforms, malformed or stale approvals remain BLOCK. No tests-directory ignore, generic token placeholder bypass or scanner severity change.

Raw redacted scanner findings and native exit remain in private receipts as `raw_findings`; exact approved findings are `exempted_fixture_findings`, all other findings `blocking_findings`, with separate counts. Added URLs are independently blocked; changed approved value/line invalidates its exemption. A related test_target execution receipt is useful optional evidence, not a business/security proof supplied by a filename. Never delete tests or manually override F09.
