Invoke the unmodified `vendor/archify/SKILL.md` only when F03/F04 has evidenced content. Archify is an Integrated authoring and delivery Skill, not a renderer utility. Its five modes are architecture, workflow, sequence, dataflow and lifecycle. Select the mode from the reader's actual question; absent facts do not trigger a view. User-requested motion uses `meta.animation: "trace"`; otherwise retain the original static default.

## Provenance route: two modes, neither skips an evidenced diagram

F03/F04 route items declare `provenance_mode`. `REPOSITORY_BACKED` requires a real clean Git root, approved credential-free origin, real full 40-character HEAD, explicit `archify_provenance.repository_evidence_required=true` and `origin_approved=true`, and approved publication scope. Inspect committed bytes; use native `meta.repository`, repository-relative sources and `--repo-root`. Never invent a remote, revision, or GitHub link; working-byte SHA is not a commit. The conservative helper selects LOCAL for dirty/multiple roots or identity unavailable; an intentionally local run remains LOCAL even if it has Git.

`LOCAL_CONTENT_BOUND` covers non-Git, no origin, private/untrusted origin, not-yet-created remote and local-only/not-authorized scope. Keep canonical project root, each relative source path/SHA256, claimed fact and inspection purpose in the private run. Use `python scripts/archify-routing.py evidence <root> <claims.json> <private-evidence.json>`. Evidence source records require `path`, `supports`, `purpose`; the helper hashes current bytes and rejects escapes. For several approved roots, bind each separately. Source entailment remains the Agent's judgment.

Local typed JSON omits `meta.repository` and unverifiable repository `sources`; it retains all nodes, edges, labels, failure/return conditions and reader scope. Run the same native finalize command **without `--repo-root`**, then all native gates, applicable visual-check, actual themes/interactions and canonical export. No origin / no GitHub / not published never justifies F04 SKIP/BLOCKED. Only absent workflow facts justify SKIP. Missing Node/browser, corrupt vendor, insufficient facts, safety/schema/semantic failure, or exhausted layout AND decomposition failure remain real blockers.

A failed repository attempt can switch only for missing origin / repository identity or provenance unavailable, after rechecking local facts. Preserve its failed receipt and candidate. `archify-routing.local_candidate` removes only repository metadata/references; geometry/semantics failures are not provenance failover. Author a fresh local candidate and finalize without repo-root; do not drop Archify, exceptions or quality/browser gates.
