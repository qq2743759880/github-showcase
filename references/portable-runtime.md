# Portable github-showcase candidate

Extract the candidate ZIP into a fresh directory and work from its `github-showcase/` root. Its `portable-manifest.json` declares Execution, complete Redistribution and verification resources by exact path and SHA-256. The product's own README/images/docs, adapter examples, development history, caches and receipts are not part of this runtime. Regression test sources are included only as explicitly declared verification resources; no historical fixture or result is required.

Run `python scripts/doctor.py`. Python is Required. Node >=24, a Chrome/Chromium browser, Snap-X, Archify and Git are Phase-specific; the GitHub backend is Optional for local generation. A missing optional tool is reported without failing an unrelated phase. Supply a route plan with `--plan <plan.json>` to diagnose the actual execution selection. Doctor checks presence and locked sources; it does not attest a render or GitHub write access.

Install pinned Node rendering dependencies with `npm ci` when F03/F04/F06 requires them. A preinstalled browser can be selected through `ARCHIFY_CHROME` and `PUPPETEER_EXECUTABLE_PATH`; use `PUPPETEER_SKIP_DOWNLOAD=true` during installation when using that external browser. No browser binary, node_modules or npm cache is shipped. Markdown YAML adapters optionally need PyYAML from the separately declared requirements; JSON routing and non-Publication gates use Python's standard library. Actions Publication permission checking conditionally uses the same pinned PyYAML parser; install `python -m pip install PyYAML==6.0.3` when a public workflow is included.

`doctor.py --runtime-config <json>` accepts `tools` entries such as node, git and browser from the target environment. This config stays local; paths must describe capabilities on that installation, never paths copied from a developer machine. Vendor wrappers and gates resolve package resources from their own file location; adapters and runs resolve their actual target scope.

After installation run `python scripts/verify-vendors.py` and `python -m unittest discover -s tests -p "test_*.py"`. The latter creates fresh temporary test targets rather than reading development workspaces. Then let a fresh Agent load this Skill and generate a local export from a fresh real target, following its native route and full gates. Keep that run outside the runtime root and do not publish unless separately authorized.

L1 means actual same-machine relocation without reading the mother workspace. L2 means fresh artifact extraction and install with no historical workspace, plus a real target run. L3 requires execution on another machine or OS; source inspection does not establish it. Candidate verification does not authorize Stable publication.

The portable manifest also classifies every original member by its consumer: ALWAYS_RUNTIME, PHASE_RUNTIME, VENDOR_NATIVE_REQUIRED, NATIVE_EXAMPLE_REQUIRED, VERIFICATION_ONLY or LEGAL_ONLY. Only verified UNREACHABLE members may be pruned; locked native examples and conditional methods remain available. Legal and test-only files are redistributed separately from Execution. The mixed optional YAML / verification requirements file has a phase installation consumer; its name alone does not make it test-only. Counts are inventory results, not reduction targets. The generated portable-manifest.json is package metadata in addition to the original member closure.

The portable manifest declares `publication: []`: public CI/release/deployment files belong to a target repository Publication Surface and are not copied into this installation redistribution. The generic contract and its consumers remain Runtime resources. See [distribution surfaces](distribution-surfaces.md).
