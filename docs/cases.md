# 三个真实案例（本方法真实跑过的项目）

> 同一套方法在三种项目形态上的路由差异。所有数字回源到各 run 的落盘证据（过程记录在维护者侧运行目录，此处给出结论与指针）；对外一律称「项目维护者」。

## Case 1 · local-codebase-mcp —— 真实代码项目

**形态**：本地代码库智能检索 MCP 服务（Python）。代码项目触发 `source_release` 硬规则：源码随包 + 全新 clone 实测。

| 维度 | 本方法做了什么 | 结果（全部实测） |
|---|---|---|
| 取证 | 现场取证，逐条带源码行号 | 工具数 15（注册计数）、模块 9 个 2321 行（逐行计数）、测试文件 25 个（目录清点） |
| 架构 | 系统上下文 + 容器两层，少而精 | 两张图，逐节点源码锚点映射 + 禁边表 |
| 流程 | 画真实用户流程 | 部署接入 / 首轮取证 / 受控写冲突回路 三链路 |
| 能力图 | 只用回源实测数字 | 能力/验证图一张，逐值核对 |
| 安全模型 | 单独成文 | 静态基座 8 项 + 受控写 10 环链逐环表 |
| 源码发布 | entry_points 5/5 随包 | **全新 clone 三步实测：装依赖 → 启动检查 exit 0 → 测试 326 passed**（与既有基线一致，0 failed） |

**为什么这算「验证过」**：README Quick Start 引用的每个文件、每条命令都在包内存在，且在全新 clone 上被这样执行过——不是「应该能跑」，是「刚跑过」。

**证据指针（维护者侧）**：`usage/phaseA/final-verdict.md`（326 passed 实测行、资产消费表）、`usage/phaseA/trace/f10-trace.md`、`usage/phaseA/trace/fresh-clone-verify.md`、基线 `usage/run-003b/trace/fresh-clone-verify.md`。

## Case 2 · dy助手 —— 纯设计方案（最容易造假的形态）

**形态**：抖音视频自动解说制作 Skill 的**设计方案**，无实现代码。最高风险是把设计说成实现。

| 维度 | 本方法做了什么 | 结果 |
|---|---|---|
| 数据图 | 契约无任何量化数据 → **F05 整相不路由** | 包内零编造数字 |
| 演示段 | 演示素材不可用 → **F07 整相不路由**，不建 demo 目录 | 无占位件、无伪造录制 |
| 设计-实现边界 | 五道防线：取证结论入事实权威 / 契约禁画「已运行系统」边 / 肯定式完成声称机检（叙事与审查两处）/ 视觉卡状态标记 / README 五处显式声明 | 机检命中均为否定式边界声明 |
| 诚实边界 | Quick Start 无可运行路径 → 如实呈阻塞态；许可未定 → 如实写「未定」并入审查待决 | 发布阻断项显式登记，不由编排方代决 |

**为什么这算「守住」**：对无实现的项目，最大的展示风险不是没内容，而是把「计划」写成「已建成」。五道防线让越界表述在叙事、图、视觉、机检四层都会被拦。

**证据指针（维护者侧）**：`usage/run-002/final-verdict.md`（交付对账、设计-实现边界专项、Gaps 逐条）、`usage/run-002/route-plan.md`（F05/F07 不路由理由）。

## Case 3 · 知识库系统 —— 复杂多知识库（最容易画错关系的形态）

**形态**：多知识库体系（组织包含 / 知识来源 / 消费三类关系并存）。最高风险是画出不存在的关系或泄漏私有事实。

| 维度 | 本方法做了什么 | 结果 |
|---|---|---|
| 事实输入 | 预核事实已冻结（公开投影）→ F01 按契约跳过 | 叙事只消费公开投影 |
| 架构图 | 三类关系分开画例（知识来源 / 消费 / 组织归属），契约未来关系用虚线 | 11 节点 + 7 边逐条映射；**三库间 runtime 调用零绘制并显式声明「不存在的边」** |
| 流程图 | 用例驱动 | 7 张图全部通过官方渲染引擎语法线 |
| 规模图表 | 只用真实数字 | 两张图渲染 exit 0、逐值核对全过 |
| 范围审查 | 凭据扫描 + 隐私双轴 + 人工三分 | 扫描空命中，且用阳性对照实证引擎在位 |
| 范围审查（反面案例） | 对一个导出候选文件：扫描命中凭据对，人工三分确认不可归示例键 → **判 BLOCK，打包面 STOP，候选未并入** | 「secret 拒绝不得绕过」的真实执行记录 |

**为什么这算「复杂度被驯服」**：多知识库的展示难点是关系语义（谁包含谁、谁消费谁）与私有边界。方法用「禁画边显式声明」强迫把不存在的关系说出口，用范围审查把私有事实挡在包外。

**证据指针（维护者侧）**：`usage/phaseC/final-verdict.md`（交付对账、消费表）、`usage/run-001b/final-verdict.md`（候选 BLOCK → F10 STOP 的完整裁决）、`usage/run-001/f0X-trace.md`（首版全链）。

## 三案例共同点

同一契约、同一十槽位、同一四道质量门；差异只来自项目形态与事实状态。**该跑的相跑实，不该跑的相显式跳过**——这就是「可验证的展示」与「写一篇好文章」的区别。
