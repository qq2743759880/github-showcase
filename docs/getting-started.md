# 加载与首次使用

下载固定版本 ZIP 并解压，进入其中的 `github-showcase/`。保留完整相对路径、许可证与按需方法资源。不要把公开仓的图片、展示文档或 Pages 配置当作安装依赖。

需要能读文件、执行工具的 Agent 与 Python；图像和图表使用 Node.js 24+，交互图和 C4 需要 Chrome/Chromium，源码打包使用 Git。预装浏览器与可选 YAML 依赖按[环境说明](../references/portable-runtime.md)配置。

在 Codex 中，将完整解压目录放入本机 Skill 发现目录，或让已有入口指向该目录；同名 Skill 保留一个发现入口。其他宿主按各自规则配置。无需自动发现时，明确让 Agent 读取解压目录的 `SKILL.md`。

`python scripts/doctor.py` 默认报告工具能力；传入实际 route plan 才诊断本次所需阶段。`python scripts/verify-vendors.py` 核对内置原始资源。依赖安装不等于已经完成图片渲染、业务审查或远端发布。

## 第一次任务

使用[README 中的首次使用请求](../README.md)，明确项目范围、目标读者、公开范围和一个新的输出目录。首次有用结果是该任务实际需要的文档、资产、源码包与私有验证记录。

## 恢复中断任务

```text
读取本次任务已有记录，核对当前源码、输出与检查证据。
修复失败项并重新验证，不覆盖未知的用户改动，不沿用失效的 PASS。
只在通过本地检查后继续已授权的发布，并回读实际远端内容。
```

普通展示和环境问题应自主修复。真实凭据、私人信息、许可与越权问题必须纠正后再公开。脚本不能代替业务语义判断，也不能保证整个宿主无法绕过入口。
